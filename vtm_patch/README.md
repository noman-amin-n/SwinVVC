# VTM Patches

Two patches against a clean VTM-20.2 checkout. Both were generated by diffing the
official release against the working tree used for the paper, and applying both
reproduces that tree byte for byte.

| Patch | Files | Purpose | Needed for |
|---|---|---|---|
| `01-partition-override.patch` | 4 | reads the predicted partition modes and reduces the RDO candidate list to one | the fast encoder |
| `02-block-statistics-tracing.patch` | 2 | enables CSV block statistics so ground-truth partitions can be extracted | label extraction |

The two builds are separate. Label extraction needs tracing but must keep the
unmodified RDO search. The fast encoder needs the override and should have
tracing off, since tracing costs runtime and distorts timing measurements.

## Apply

```bash
git clone https://vcgit.hhi.fraunhofer.de/jvet/VVCSoftware_VTM.git
cd VVCSoftware_VTM
git checkout VTM-20.2

# build B, the fast encoder
git apply --whitespace=nowarn /path/to/SwinVVC/vtm_patch/01-partition-override.patch

# build A, label extraction (in a separate checkout)
git apply /path/to/SwinVVC/vtm_patch/02-block-statistics-tracing.patch
```

Use `git apply --check` first to confirm a patch applies. `--whitespace=nowarn` is
needed for patch 01 because a few added lines carry trailing whitespace from the
original source.

## 01-partition-override.patch

| File | Change |
|---|---|
| `source/Lib/CommonLib/Picture.h` | `m_pCUDepth` member and its accessors |
| `source/Lib/EncoderLib/EncModeCtrl.h` | declares `getVecCompr`, `ChangeTestMode`, `Modify` |
| `source/Lib/EncoderLib/EncModeCtrl.cpp` | `ChangeTestMode` reduces the RDO candidate list to the predicted mode, `Modify` restores the full list when that mode is not allowed |
| `source/Lib/EncoderLib/EncCu.cpp` | tracks the CTU address, loads `POC_<n>.txt` per frame, overrides the candidate list for 32x32 luma CUs |

Before building, set the HCPM input path. `EncCu.cpp` hard-codes the directory it
reads prediction files from, and it must be edited for each sequence and QP. See
[../docs/vtm_integration.md](../docs/vtm_integration.md) section 3.1. The file
open is unchecked, so a wrong path fails silently.

## 02-block-statistics-tracing.patch

| File | Change |
|---|---|
| `source/Lib/CommonLib/TypeDef.h` | `ENABLE_TRACING` 0 to 1, `BLOCK_STATS_AS_CSV` 0 to 1 |
| `source/Lib/CommonLib/dtrace_blockstatistics.cpp` | comments out an `assert(0)` on the chroma intra mode tracing path that otherwise aborts the encoder |

`BLOCK_STATS_AS_CSV` produces the semicolon separated
`BlockStat;<poc>;<x>;<y>;<w>;<h>;<statistic>;<value>` records that
`swinvvc.data.dtrace` parses. Without it the trace uses a human readable format
the parser does not accept.

Full details, the 341-entry HCPM layout and troubleshooting are in
[../docs/vtm_integration.md](../docs/vtm_integration.md).
